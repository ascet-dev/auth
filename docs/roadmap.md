# Roadmap

## Админы

- [x] админская аутентификация + bootstrap owner-а — план: [admin_auth_plan.md](admin_auth_plan.md)
- [x] admin CRUD API: client apps, коннекторы, identities (read), sessions, login audit, grants

## UI

- [x] админский логин
- [x] админка (SPA): client apps, коннекторы, identities, sessions, login audit, grants
- [ ] **клиентский UI (IAM-подобный, как в Authentik/Auth0)** — чтобы интеграцию можно было
      собрать и проверить из интерфейса, не читая README и не собирая curl-и руками:
  - конструктор экранов входа для своего приложения (какие способы показывать, порядок, брендинг)
  - настройка redirect URI и проверка их валидности прямо в UI
  - «попробовать вход» — прогнать реальный логин выбранным коннектором и увидеть,
    что вернулось: сессия, access/refresh, распарсенный payload токена
  - готовые сниппеты интеграции (curl / JS / Python) с подставленным client_app_id
  - публичная страница входа, которую можно отдать пользователям как есть (hosted login page)

## Способы входа

- [x] коннекторы: несколько экземпляров одного типа (два TMA-бота, два OAuth-приложения)
- [x] привязка коннекторов к приложениям (M2M), парольные политики per-app
- [ ] OTP (SMS/email) — модель и эндпоинты есть, логика не реализована
- [ ] OAuth: проверка `state` и верификация `id_token` — **обязательно до появления первого
      OAUTH-коннектора в проде** (см. [tech_debt.md](tech_debt.md))

## Инициализация (визард для разворачивания приложения)

- [x] скачал с github, запустил одну команду, получил развёрнутый инстанс с интерфейсом
      (`make init`: ключи → docker-стек → миграции → сид → bootstrap → backend + SPA)
- [ ] setup-визард в UI: смена пароля владельца при первом входе, пошаговая настройка
